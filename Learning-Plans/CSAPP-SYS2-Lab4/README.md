## 1. 我究竟在学什么：一条从 SYS1 连到 Lab4 的路

```text
SYS1 / SYS2 前几次实验：我搭建 CPU，让它取指、译码、执行
    ↓ 现在先假设“CPU 可以执行 RISC-V 指令”
程序源代码：C 与 .S（汇编）
    ↓ 编译器：变成 .o（机器指令和待解决的引用）
链接器：把多个 .o 连成 vmlinux，确定函数和代码的地址
    ↓ vmlinux.lds 决定布局，例如从 0x80200000 开始
QEMU：在电脑里模拟一台 RISC-V 机器
    ↓ OpenSBI：先在较高特权级初始化，并把控制权交给 Kernel
head.S 的 _start：初始化 sp（栈指针）
    ↓ 跳入 C 函数 start_kernel
Kernel 要输出文字
    ↓ sbi_ecall：按寄存器约定请求 OpenSBI 服务
终端出现欢迎语 → 再观察 System.map / GDB 证明自己理解
```

特别注意：

- **CPU** 是执行指令的硬件（在 QEMU 中由软件模拟）；**Kernel** 是运行在 CPU 上的操作系统核心软件；**QEMU** 是模拟机器的工具，不能证明你亲自写的流水线 CPU 一定正确。
- **OpenSBI 不是 Kernel**：本实验用它作为底层固件与 SBI 服务提供者。M-mode（机器级）比 S-mode（内核通常使用）权限更高；U-mode 是普通用户程序。
- **普通 Linux system call** 通常是用户程序请求 OS 内核服务；**SBI ecall** 是这里的 S-mode Kernel 请求更底层的 OpenSBI 服务。两者都涉及受控的调用/陷入机制，但不是同一个接口。
- **地址** 是内存中的位置，不是文件名。Lab4 官方说明：OpenSBI 初始化后进入 `0x80200000` 处的 Kernel。

## 2. 拓扑阅读：先学这个，才能看懂后面那个

按 **CSAPP 第三版** 的节号。若实体书版本不同，优先匹配中文标题。预计时间只是阅读预算，可按实际情况缩短；**不把课本阅读当成动手实验的替代品**。

### L0｜最少系统直觉：没有 OS，CPU 能执行指令吗？

**先读：第 1 章 1.1～1.4；然后 1.7《操作系统管理硬件》**。预算 40–60 分钟。

- 为什么先读：你已经知道 PC / RegFile / ALU，但还没把“程序文件、机器指令、CPU、操作系统”连成一条线。
- 白话版：C 代码是人读的文字；处理器最后执行的是机器指令；操作系统平时负责管理资源，并不是每次加法都亲手代算。
- **读完必须能讲**：`add` 谁来算？编译器做什么？操作系统在普通程序运行中主要提供哪些帮助？QEMU 又在哪一层？
- **落到 Lab4**：找到 `src/project/kernel/Makefile` 里 `gcc`、`ld`、`qemu-system-riscv64` 三个名字，说出三者分别负责什么。
- [ ] 看过指定节，并且闭书说明“CPU、Kernel、QEMU、编译器、链接器”各自作用。

### L1｜函数调用为什么要栈：专门为了 head.S

**再读：第 3 章 3.4《访问信息》（扫一遍寄存器）与 3.7《过程》（重点：调用、返回、栈帧）**。预算 40–60 分钟。

- 前置：先知道寄存器是 CPU 内的小型快速存储，内存另有地址。
- 新词 **stack / 栈**：内存里预留给函数调用等用途的区域；**sp / 栈指针**：指示当前栈顶位置的寄存器。函数可能借栈保存返回地址、局部数据。
- 重要：CSAPP 第 3 章以 **x86-64** 举例；本实验 **RISC-V 的 `sp` 是 x2**，不能把两套汇编语法混用。
- **读完必须能讲**：函数调用为什么可能要栈？为什么 Kernel 启动时不能假定栈已经准备好了？
- **落到 Lab4**：官方要求 `head.S` 把 `sp` 设置为 `_ekernel + 4096`（4 KiB），然后跳到 `start_kernel`。自己画地址布局并计算：若 `_ekernel=0x80208000`，则初始 `sp=0x80209000`。
- [ ] 能画出 `.text/.rodata/.data/.bss` 后的 4 KiB 栈，并解释 `_start → 设置 sp → start_kernel`。

### L2｜C 文件为什么不能直接“扔给 CPU”：专门为了 Makefile、vmlinux

**接着读：第 7 章 7.1《编译器驱动程序》、7.3《目标文件》、7.4《可重定位目标文件》、7.7《重定位》、7.8《可执行目标文件》、7.9《加载可执行目标文件》**。预算 60–90 分钟，可拆两次。7.2/7.5/7.6 先按需要回查，不必立即精读。

- **.c/.S**：源码；**.o**：编译/汇编的中间产物；**ELF**：一种保存程序代码、数据和元信息的文件格式；**vmlinux**：本实验链接得到的 RV64 ELF 文件。
- **link / 链接**：把散在不同文件里的函数/数据地址关系接起来；**loader / 加载**：把程序放进适合执行的内存环境。它们不是同一个动作。
- **section / 段**：代码与数据的分组。`.text` 放代码，`.rodata` 放只读数据，`.data` 放已初始化全局数据，`.bss` 放未初始化全局数据。
- **vmlinux.lds**：链接脚本；本实验用它确定内核内存布局，入口 `_start`、基址 `0x80200000` 等；**System.map**：方便查函数/符号对应地址的表。
- **读完必须能讲**：多个 `.o` 怎么变成 `vmlinux`？为什么 `_start` 能对应一个确定地址？`System.map` 是拿来干什么的？
- **落到 Lab4**：补 `arch/riscv/kernel/Makefile` 的编译构造规则；观察 `make` 的执行和 `vmlinux.asm`、`System.map`。
- [ ] 能口述 `源文件 → .o → vmlinux → QEMU 中执行`，并在实际工程中指出每一步。
- [ ] 能解释为什么“编译成功”不等于“内核已经启动成功”。

### L3｜软件如何请求特权服务：专门为了 sbi.c、sbi.h、print.c

**再读：第 8 章 8.1《异常》（尤其理解异常/陷入的分类和系统调用例子）**。预算 30–45 分钟。第 8 章后面的进程/信号内容先不硬啃。

- **特权级**：不同代码能做的事情受限制。课程中的 U/S/M 是 RISC-V 的三类执行权限；它不是三个不同 CPU。
- **ecall**：软件执行的环境调用指令；可理解为“按约定向更高权限的执行环境提出服务请求”。本实验细节看 SBI 文档而不是照抄 CSAPP x86 示例。
- **SBI / OpenSBI**：SBI 是接口规范；OpenSBI 是实现它的固件。当前实验从 Kernel（S-mode）调用服务到 M-mode。
- **a0～a7**：RISC-V 约定的参数/返回值寄存器。本实验 `sbi_ecall`：a7 放扩展 ID（eid），a6 放功能 ID（fid），a0～a5 放 6 个参数；返回后 a0 是错误码、a1 是返回值。
- **CSR / csr_read**：CPU 用来表示/控制状态的特殊寄存器，以及读取它的宏；不是普通 C 变量。
- **读完必须能讲**：Kernel 想输出一个字符时为什么可以借助 OpenSBI？为什么调用前要给指定寄存器赋值？
- **落到 Lab4**：实现 `sbi_ecall`（内联汇编）、`puts`（逐字符输出）、`puti`（整数转字符输出）与 `csr_read` 宏。官方给出测试：DBCN 的 write-byte 服务能输出 ASCII `0`。
- [ ] 能画出 `C 调用 → a0~a7 → ecall → OpenSBI → 返回 a0/a1`，且能解释每个寄存器的用途。

## 5. 12 个白话词典（遇到新词先查这里）

| 术语 | 先这样理解 | 在 Lab4 里对应 |
| --- | --- | --- |
| CPU | 按指令做事情的执行者 | 执行 Kernel 的 RISC-V 指令 |
| Kernel（内核） | 管理计算机资源的核心程序 | `start_kernel` 等内核代码 |
| QEMU | 在电脑里“模拟出一台另一种机器” | 模拟 RISC-V 机器 |
| Docker | 带着工具和依赖的一套可复现运行环境 | 助教会用的测试环境 |
| Compiler（编译器） | 把源代码处理成机器可用的目标代码 | `riscv64-linux-gnu-gcc` |
| Makefile | 自动化“先做哪步、用什么命令”的菜谱 | 生成目标文件与 Kernel |
| Linker（链接器） | 拼接目标文件、确定引用和布局 | `ld` 生成 `vmlinux` |
| ELF / vmlinux | 一种程序文件格式 / 本实验内核可执行文件 | `file vmlinux` |
| Loader / Boot | 把程序安排到运行环境 / 从启动到进入内核 | QEMU、OpenSBI、`head.S` |
| Stack / sp | 函数调用可能使用的内存区 / 指向栈顶的寄存器 | `head.S` 设置 sp |
| OpenSBI / SBI | 底层固件实现 / S-mode 向固件求助的接口规范 | `sbi_ecall` |
| CSR / ecall | CPU 状态控制寄存器 / 请求环境服务的指令 | `csr_read`、`sbi.c` |

注：这里是入门直觉，不代替完整架构定义。
